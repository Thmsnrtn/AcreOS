# Thread 1 — Six tabs, one thread

## Tweet 1 (hook — 261 chars, stands alone)

> A property investor's workflow used to live in six tabs.
>
> Tab 1: county GIS. Tab 2: a comp tool that doesn't price vacant land. Tab 3: mail merge. Tab 4: a CRM that doesn't know what a parcel is. Tab 5: a spreadsheet for the note. Tab 6: an inbox burying every reply.

## Tweet 2 (203 chars)

> One thread per parcel, from cold lead through closed note.
>
> List-pull, comp analysis, mail draft, seller reply, deal close, note service — same parcel, same thread, same audit log. Nothing forks into a tab nobody opens again.

## Tweet 3 (243 chars)

> The platform is built for Land Investors first.
>
> Note Investors are core. Fix-and-Flippers, Wholesalers, and Tax-Delinquent Buyers are in beta. Subdividers and Buy-and-Hold Landlords are on the roadmap.
>
> The tier is on the page, before signup.

## Tweet 4 (215 chars)

> Why the beta tag stays visible: a "Beta" label below the hero costs short-term conversion. It saves the trust the platform actually runs on.
>
> Honesty scales better than feature inflation. That is not a slogan; it is an architecture choice.

> · the seller reply (when it arrives)
> · the deal record
> · the note, after close
