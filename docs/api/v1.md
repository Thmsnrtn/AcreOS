# AcreOS Public API — v1

Status: **scaffold / not yet open to traffic** (Lens 50, Public API v0 design).

This document describes the API surface that will be exposed at
`https://api.acreos.com/v1/*` once the feature is enabled. The
endpoints, auth model, error shape, and webhook signing scheme are all
final for v0 — once we open the surface, breaking changes go through
the `Changelog` policy at the end of this doc.

---

## Base URL & versioning

```
https://api.acreos.com/v1
```

Version is in the path. v1 is the only currently-supported version.
We promise:

- Additive changes (new endpoints, new fields on existing responses, new
  optional request fields) are non-breaking and ship without a version bump.
- Removing a field, changing a field's type, or changing default behavior
  is a breaking change and ships under `/v2`. v1 will run in parallel for
  at least 12 months after `/v2` reaches GA.

## Authentication

Every request requires a bearer token:

```
Authorization: Bearer ak_live_xxxxxxxxxxxxxxxxxxxxxx
```

API keys are created at **Settings → API Keys** (admin role only). Each
key carries a set of **scopes** — the scope vocabulary is:

| Scope              | Grants                                          |
| ------------------ | ----------------------------------------------- |
| `leads:read`       | `GET /v1/leads`, `GET /v1/leads/:id`            |
| `leads:write`      | `POST /v1/leads`, `PATCH /v1/leads/:id`         |
| `properties:read`  | `GET /v1/properties`, `GET /v1/properties/:id`  |
| `properties:write` | `POST /v1/properties`                           |
| `deals:read`       | (reserved — v0.1)                               |
| `deals:write`      | (reserved — v0.1)                               |
| `notes:read`       | (reserved — v0.1)                               |
| `notes:write`      | (reserved — v0.1)                               |
| `webhooks:write`   | `POST /v1/webhooks`, `GET /v1/webhooks`, `DELETE /v1/webhooks/:id` |

Test-mode keys (`ak_test_…`) are also supported. They behave identically
but never trigger outbound webhooks — useful for local development.

The plaintext token is shown **exactly once** at creation time. We
persist only an HMAC-SHA256 hash with a server-side pepper. Lost keys
cannot be recovered, only regenerated.

## Response envelope

Every successful response is JSON of the form:

```json
{
  "data": <T | T[]>,
  "meta": {
    "request_id": "9e3b...",
    "rate_limit": { "limit": 1000, "remaining": 998, "reset": 1716840000 },
    "pagination": { "next_cursor": "...", "prev_cursor": "...", "has_more": true }
  }
}
```

`meta.pagination` is present only on list endpoints. `meta.request_id`
is mirrored from the `X-Request-Id` response header — include it when
filing support tickets.

## Errors

```json
{
  "error": "VALIDATION_FAILED",
  "message": "Validation failed",
  "details": [ /* zod issues */ ],
  "statusCode": 422,
  "docsUrl": "https://docs.acreos.com/api/errors#validation-failed"
}
```

| `error`               | Status | Meaning                                          |
| --------------------- | ------ | ------------------------------------------------ |
| `UNAUTHORIZED`        | 401    | Missing or invalid bearer token                  |
| `FORBIDDEN`           | 403    | Token is valid but lacks the required scope      |
| `NOT_FOUND`           | 404    | Resource doesn't exist or isn't owned by this org |
| `BAD_REQUEST`         | 400    | Malformed input (e.g. invalid cursor)            |
| `VALIDATION_FAILED`   | 422    | Zod validation failure — see `details`           |
| `LIMIT_EXCEEDED`      | 429    | Rate-limit or quota exceeded — see `Retry-After` |
| `INTERNAL_ERROR`      | 500    | Server bug — include `request_id` when reporting |

## Pagination

List endpoints are cursor-paginated. There is no offset/page parameter
— this lets us preserve consistency under concurrent writes (a property
created during your walk won't shift your page boundaries).

```
GET /v1/leads?limit=50&cursor=eyJpIjoxNzIzLCJkIjoiZiJ9
```

- `limit` — 1..100, default 50.
- `cursor` — opaque base64url string from a previous response's
  `meta.pagination.next_cursor` or `prev_cursor`. Do not parse it.

`has_more` is `true` if more rows exist past the current page in the
walking direction. To walk backward, pass the `prev_cursor`.

## Idempotency

All `POST` and `PATCH` endpoints honor `Idempotency-Key: <uuid>`. If
the same key is replayed within 24 hours we return the cached response
(same status, same body). Use it for retry-safety on flaky networks:

```http
POST /v1/leads
Authorization: Bearer ak_live_…
Idempotency-Key: 2f3e1a98-9d6a-4cdb-91f8-bc04b1e9d3a1
Content-Type: application/json

{ "first_name": "Jane", "last_name": "Doe", "type": "seller" }
```

Replaying the same `Idempotency-Key` with a *different* body returns the
first response anyway — keys are not body-bound in v0. (This matches
Stripe's classic semantics. We may tighten to body-hash binding in v2.)

## Rate limiting

Per-organization, hourly sliding window. Tier defaults:

| Tier      | Requests/hour |
| --------- | ------------- |
| Free      | 10            |
| Starter   | 100           |
| Pro       | 1,000         |
| Scale     | 10,000        |

Headers on every response:

```
X-RateLimit-Limit: 1000
X-RateLimit-Remaining: 873
X-RateLimit-Reset: 1716840000
Retry-After: 412         # only on 429
```

A per-key override (`rate_limit` at key-create time) takes precedence
over the tier default — useful for partner integrations that need a
higher allowance without upgrading the customer's tier.

## Webhooks

Register an endpoint at `POST /v1/webhooks`. AcreOS will POST signed
JSON to it whenever a subscribed event fires.

### Signing

Headers on every delivery:

```
AcreOS-Event-Id: <uuid — stable across retries>
AcreOS-Event-Type: lead.created
AcreOS-Signature: t=1716840000,v1=<hex hmac>
User-Agent: AcreOS-Webhooks/1.0
```

The signature is `HMAC-SHA256(signing_secret, "${t}.${rawBody}")`. To
verify (Node example):

```js
import { createHmac, timingSafeEqual } from "node:crypto";

function verify(rawBody, header, secret) {
  const { t, v1 } = Object.fromEntries(header.split(",").map(p => p.split("=")));
  const expected = createHmac("sha256", secret).update(`${t}.${rawBody}`).digest("hex");
  return timingSafeEqual(Buffer.from(expected), Buffer.from(v1));
}
```

Reject deliveries where `|now - t| > 300` to defeat replay.

### Event payload

```json
{
  "id": "evt_2f3e1a98...",
  "type": "lead.created",
  "created": 1716840000,
  "organization_id": 42,
  "data": { /* serialized resource */ }
}
```

### Retry policy

5 attempts with exponential backoff:

| Attempt | Delay from previous |
| ------- | ------------------- |
| 1       | (immediate)         |
| 2       | +1 minute           |
| 3       | +5 minutes          |
| 4       | +30 minutes         |
| 5       | +2 hours            |
| —       | +12 hours (DLQ)     |

Any 2xx response is a success. After 10 consecutive failed deliveries
the subscription is auto-disabled; the customer must re-enable it from
**Settings → API Keys → Webhooks**.

All attempts are visible in `GET /v1/webhooks/{id}/deliveries` (v0.1).

### Events (v0)

- `lead.created`, `lead.updated`
- `property.created`, `property.updated`
- `deal.created`, `deal.updated`, `deal.closed` (reserved — v0.1)
- `note.created` (reserved — v0.1)

## Endpoint reference

### `GET /v1/leads`

Cursor-paginated list of leads. Scope: `leads:read`.

### `POST /v1/leads`

Create a lead. Scope: `leads:write`. Idempotency supported.

```json
{
  "type": "seller",
  "first_name": "Jane",
  "last_name": "Doe",
  "email": "jane@example.com",
  "phone": "+15125550100",
  "source": "zapier"
}
```

### `GET /v1/leads/{id}` · `PATCH /v1/leads/{id}`

Single-lead fetch and partial update. Same scopes as collection.

### `GET /v1/properties` · `POST /v1/properties` · `GET /v1/properties/{id}`

Mirror the leads contract. `size_acres` is decimal-as-string for
precision. `apn`, `county`, `state` are required on create.

### `POST /v1/webhooks`

Register an endpoint. Returns the `signing_secret` exactly once.

```json
{
  "url": "https://your-app.example.com/webhooks/acreos",
  "events": ["lead.created", "property.created"]
}
```

### `GET /v1/webhooks` · `DELETE /v1/webhooks/{id}`

List and revoke endpoints.

## Changelog policy

- We publish a dated entry in `docs/api/v1-changelog.md` for every
  additive change.
- Deprecations get a `Sunset` header 90 days before removal — pointed at
  the changelog entry that explains the migration.
- Breaking changes never ship to v1. They bump to v2.

## Design influences

The shape of this surface borrows from:

- **Stripe** — bearer tokens, `evt_` IDs, signature header format,
  request_id surfacing, idempotency semantics, cursor pagination.
- **Plaid** — peppered token hashes, scope-per-key model, `whsec_` secret
  format, retry table.
- **Twilio** — `Retry-After` semantics, structured error codes.

What we deliberately don't copy:

- **Stripe events list endpoint** — adds storage cost we don't need at v0
  scale. Customers can replay from their own logs.
- **GraphQL** — not in v1, not on the roadmap.
- **OAuth 2.0** — deferred to v0.1. Bearer keys cover every v0 use case
  (server-to-server integrations).
