# design-sync notes — @acreos/design-system

Repo-specific gotchas for syncing the AcreOS shadcn/ui design system.

- **Isolated workspace.** The whole design system lives in `design-system/` with
  its OWN `package.json` + lockfile so the production app's `package-lock.json`
  is untouched. It pins a STABLE toolchain (Vite 6 + Storybook 9 + TS 5.6),
  deliberately NOT the app's bleeding-edge Vite 7 / TS 6.0.2 — the components are
  framework-agnostic React, so a stable isolated builder avoids compatibility
  risk. Run all design-sync commands from `design-system/`.
- **Components are re-exported, not copied.** `src/index.ts` re-exports the REAL
  components from `client/src/components/ui/*` via the `@` → `../client/src`
  alias (set in both `vite.config.ts` and `.storybook/main.ts`). Single source
  of truth — the previews are the same components the app ships.
- **csstype / @types/react dedupe.** The app root pins `@types/react@18.3.12` +
  `csstype@3.1.3`; a fresh DS install pulled newer copies, causing
  "two different React CSSProperties" dts errors. Fixed via `overrides` in
  `design-system/package.json` pinning both to the root versions. If dts errors
  about incompatible `CSSProperties`/`alignmentBaseline` return, re-check these
  overrides match root.
- **dts excludes stories.** `vite-plugin-dts` is scoped to `include: ["src/index.ts"]`
  — the `.stories.tsx` `meta` consts otherwise leak external Props names
  (`CardProps` TS4023) that the type rollup can't re-name.
- **AcreOS Button has no `link` variant.** Its variant set is
  `default | destructive | outline | secondary | ghost | glass` (note `glass`),
  sizes `default | sm | lg | icon`. Match the REAL component API in stories, not
  shadcn defaults.
- **No React provider — `provider: {component: "Fragment"}` sentinel.** These
  components need no context provider; theming is via CSS custom properties on
  `<html data-theme>` (set globally), not a React theme provider. The converter's
  provider auto-detect fiber-walks the FIRST story (alphabetically "Alert") and
  misreads its own outermost component as a provider — a false positive for any
  leaf-only DS. Setting `cfg.provider` to a non-exported name ("Fragment") makes
  emit treat it as no-wrap (`exported.has("Fragment")` is false → null wrap) and
  validate falls back to `React.Fragment`, while preventing the converter from
  re-writing the bogus Alert provider into the config each build. If you ever add
  a real provider, set it here properly. The build still logs an informational
  `[PROVIDER_DETECTED] Alert` — ignore it; the sentinel wins.
- **`[FONT_MISSING] lexend variable`** is benign: Lexend is an OPT-IN
  accessibility font (`html[data-font="lexend"]`), not in the default previews.
  The "Lexend" @font-face + woff2 DO ship; only the "Lexend Variable" alias name
  lacks its own face. Non-blocking (validate exits 0).
- **Full set synced (59 components, 7 groups).** Scaled from the 5-component
  proof to the whole shadcn/ui set. `src/index.ts` is AUTO-GENERATED by
  `.ds-sync/gen-index.mjs` from the real exports (drops type-only exports like
  `CarouselApi`); stories by `.ds-sync/gen-stories-{1,2}.mjs`; groups assigned by
  `.ds-sync/regroup.mjs` (title prefix `Group/Name` → pane group). Re-run those
  if components change, then rebuild.
- **Heavy component deps resolve from root, not listed here.** recharts, embla,
  react-hook-form, cmdk, vaul, react-day-picker, etc. resolve via upward node
  resolution to the repo-root `node_modules`. `resolve.dedupe: [react,react-dom,
  react/jsx-runtime]` in BOTH vite.config.ts and .storybook/main.ts keeps a
  single React so hooks don't break. The lib bundle is ~1.8MB as a result.
- **Storybook: docgen + dts off.** `.storybook/main.ts` sets
  `typescript: { check:false, reactDocgen:false }` (avoids parsing the full
  client type graph — `import.meta.env` TS2339 from analytics/sentry/clientLogger
  — and speeds the build) and its `viteFinal` STRIPS the inherited
  `vite-plugin-dts` (Storybook auto-merges the root vite.config.ts; the dts
  plugin chokes on re-exported const arrows like `AlertDialogFooter`).
  `tsconfig.json` adds `types: [vite/client, node]` for the lib dts build.
- **Global TooltipProvider decorator** in preview.ts — components that use a
  Radix tooltip internally (e.g. ConversionFunnel) need it; wrapping every story
  avoids per-story providers.
- **Omitted from cards (still in the bundle):** `VerticalBadge` (app-coupled:
  useContextProfile + react-query), `FiltersChip` (`md:hidden` — mobile-only,
  legitimately invisible on the desktop preview viewport), `InputOTP` (renders
  empty without focus/value), `Toast` primitive (Toaster covers the surface).
- **Verified real APIs differ from shadcn defaults:** Button has `glass` not
  `link`; DealJourney takes `status` (not steps); FiltersChip takes `onClick/count`;
  StatusDot takes `tone` (green/amber/red/blue/gray/purple); ConversionFunnel
  takes `stages:{key,label,count,color}`; ExportButton takes `entity`; PageHeader
  uses `description`. Always read the source before writing a story.
